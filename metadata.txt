about=Morizon Next is an independent, unofficial continuation of MORIZON (もりぞん), a forest zoning support tool originally developed through a project commissioned by the Forestry Agency of Japan. It inherits the original's approach of examining forest management direction from both forestry profitability and mountain disaster risk, together with its core processing framework, and adds automatic data acquisition (DEM, site index data, buildings and road edges), a work-system editor, and saving/resuming an analysis. This plugin is for Japan only; site index data is available only in zones I to XIII of the Japan Plane Rectangular Coordinate System. Automatic download of buildings and road edges requires a free user account for the GSI Fundamental Geospatial Data download service. Terrain complexity is computed within the plugin, so SAGA is not required (a SAGA route is kept, but current SAGA versions give results that differ substantially from the original, so it is not intended for normal use). Automatic data acquisition requires an internet connection. Acknowledgements: the original MORIZON was developed through a project commissioned by the Forestry Agency of Japan, with the zoning workflow organized by the Japan Forest Technology Association and the QGIS plugin implemented by MIERUNE Inc. Morizon Next is not an official release of the Japan Forest Technology Association or the Forestry Agency of Japan.

changelog=
    0.1.5 - Elements tab: an Edit button on the building and road rows starts editing the roads and buildings layer on the map, and saving the edits updates the files used for the calculation. Roads you draw are shown as a road network, apart from the downloaded road edges. Zone statistics: the high disaster risk share can now be set up to 100 percent, and a standard value can be set in the settings tab; existing results keep the value they were made with. The conifer filter no longer keeps the values of a removed layer, and no longer offers the fid column. Layer lists for selecting your own layers now follow the Layers panel order. DEM browser: the area can optionally be made a circle inscribed in the map view. Site index data is now clipped on the original 50 m grid instead of being resampled, so its values match the original data. Elements calculation: the progress window now shows the current step within each element, with its progress where available, and keeps the same height while running. Elements tab: a site index map made from airborne LiDAR data (one GeoTIFF, as in section 4.2 of the zoning manual) can be imported with the 取込 button on the site index rows; it is calculated as an extra element, 地位（独自）, and can be chosen in the 地位スコア row of the scoring tab. The import window shows the conditions recorded in the map, such as those written by fcloud_shizuoka. Manual: section 1.9 now explains, for each element, what the downloaded public data lacks and where local data can come from, including the 2 km guideline for 保全対象 and how a 1 m DEM changes the meaning of some elements. Elements tab: before the calculation, buildings and roads whose coordinate system is unknown and whose coordinates do not fall on the DEM (for example, latitude and longitude without a .prj file) are now reported instead of silently giving an empty result, and you are asked before continuing when no building falls on the DEM. When the buildings overlap no catchment in the area, a notice now says that 保全対象を含む流域 is 0 everywhere. The … buttons of the input rows can now always be used, so your own files can be chosen without fetching data first. Scoring: the site index layer used (スギ, ヒノキ, カラマツ or 地位（独自）) is saved with the thresholds and restored when resuming. Manual: sections 1.4 and 2.1 explain that a 1 m DEM gives a source-oriented view and a 10 m DEM a catchment-oriented view. Zone statistics: the polygon layer list has a new choice, 現在地の樹種メッシュ, which downloads the national forest resource mesh (Forestry Agency, 20 m) for the area of the zoning map and fills in the conifer filter with its tree species (the filter is left unchecked). The mesh layer is placed below the zoning map, is shown and hidden together with it, and is removed after the zone statistics are run; downloaded sheets are kept and not downloaded again. Switching tabs and other operations no longer hide or collapse the roads and buildings group in the Layers panel. Resuming from saved data now also restores the zoning thresholds used for the zoning map. Scoring tab: the statistics button now also recolours that element and shows it on the map, like the other operations on the row, and a 地図に表示 button on the 保全対象を含む流域 row shows that layer on its own. Minor UI adjustments.
    0.1.4 - Added a link (overseas_research) at the bottom left of the window that opens the author's notes, in Japanese and English, on what the site index data means and what would be needed to use the plugin outside Japan, as a guide for preparing your own data. Manual: added a caution not to treat the site index as a correct value. Fixed resuming from saved data resetting the scoring thresholds to their initial values; the thresholds used when scoring was run are now restored, so re-running scoring after resuming no longer changes the results. Scoring tab: changing a threshold, choosing a layer, using the statistics view or the initial-value button now recolours that element on the map at once and shows it on its own with its legend open in the Layers panel; the Update and Back buttons have been removed. Loading saved thresholds also recolours the elements. The Layers panel now follows the work: after each step is run, results from the other steps are hidden and collapsed, and switching tabs opens and shows what that tab works on (the scoring results on the zoning tab, the zoning map on the zone statistics tab). Print layouts: the legend of the zone statistics layout no longer runs off the page, and the zoning map and zone statistics layouts now use the same scale and centre so that the two maps and their backgrounds line up. Work-system CSV: a CSV chosen with the "…" button is now checked before the elements are calculated, and if it cannot be read correctly, the row to fix is shown. Minor UI adjustments.
    0.1.3 - [IMPORTANT] The fetched DEM is now checked against the site index data (MORIZON dataset). Where the DEM area has no matching site index data, such as remote islands like the Izu Islands, processing stops with an explanation and the fetched DEM is deleted, because scoring and zoning cannot be completed there. GSI DEM: sea and water surfaces (lakes and rivers) are now excluded from the analysis instead of being filled with terrain that does not exist, and land not covered by the selected resolution is filled with coarser DEM (5 m, then 10 m) instead of being smoothed over. Sea and water surfaces are now excluded for every DEM source, including sources that give lakes and rivers a height value (such as VIRTUAL SHIZUOKA and the Nagano prefecture DEMs), so lakes and rivers are no longer analysed as terrain. Near the sea, lakes and rivers, slopes whose catchment cannot be determined are now left out of both the zoning map and the zone statistics, as in the original MORIZON, instead of being zoned from water surfaces that are not terrain. Zone statistics by watershed now use the same DEM as the elements by default. The resolution choice and the completion message show how much land is filled, and a file showing where the DEM was filled or excluded is saved next to the DEM. A DEM tile that cannot be read no longer stops the whole download. Fixed site index and road distance becoming 0 where the elevation is exactly 0 m. On Windows, fetching a DEM no longer fails when the file from the previous fetch is still open in QGIS. The plane rectangular coordinate zone is now chosen by prefecture as defined by law (by municipality in Hokkaido), so the DEM is saved in the correct zone and the matching ZoningKit is used; previously some areas, such as Tokyo, Nagoya, Fukuoka, Sapporo and western Shizuoka, were given a neighbouring zone. Cancelling while building and road edge data are being merged now stops at once. Downloaded road edges now include only full-width roads (真幅道路), as the zoning manual describes, so footpaths and roads inside tunnels no longer make nearby forest look easy to reach. Minor UI adjustments.
    0.1.2 - Starting an analysis now clearly uses the area shown on the map. DEM range checks now run with progress shown, and the resolution choice guides users toward 10 m DEM for wide areas to reduce processing time and data size. Zoning: you can see how the profitability and disaster risk values are spread and set the threshold while the map updates at once. Scoring results are shown right after they are made, and after zoning or zone statistics the earlier results are hidden so the new one is easy to see. Zone statistics: zones can be shown only on conifer stands, and the map can be drawn without outlines for viewing over other layers; these settings are kept. Manual: example results, how to set thresholds, and an example with the Shizuoka 20 m forest mesh. Starting from an original ZoningKit folder for zone XI or XIII, whose site index data is made in zone XII, now keeps that data as the region of the folder, so the region does not need to be downloaded again.
    0.1.1 - When site index data for a region is downloaded for the first time, a notice now explains that it may take a while and is needed only once per region. Starting from an existing original ZoningKit folder now copies its region-wide site index data into the shared data, so that region does not need to be downloaded again. The prompt to delete leftover temporary files no longer appears twice. Reorganized the manual: a quick-start guide, an overview of the automatically acquired data, and a statement of the plugin's position.
    0.1.0 - First release.
    0.1.0-dev - Fixed an issue inherited from the original MORIZON: setting the initial scoring thresholds failed with an error when the selected raster had no file on disk (such as a temporary in-memory layer added by another plugin) or was stored in a folder that cannot be written to. Temporary work files are no longer written next to the selected layer's data. The layer selectors on each tab also no longer pick up layers that other plugins add later. Improved how files and layers are handled so that the plugin does not interfere or conflict with other plugins or the QGIS environment.
